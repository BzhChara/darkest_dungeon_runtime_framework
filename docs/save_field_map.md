## Coverage Rules

- `semantic`: exported into a named `facts.*` model with stable meaning.
- `scalar`: DSON scalar path and value are visible through `facts.persistFiles`, but no dedicated semantic model exists yet.
- `raw`: field is visible but still encoded as a raw/nested payload or object-only branch, so more decoding is needed.
- `object-only`: root/object path exists in this sample, but no scalar child was decoded from it.
- `container`: object root is exported as a named facts container with existence, direct-child, descendant-object, and descendant-scalar counts.

## Parsing Backlog Before Gameplay Rules

1. `base_root.quests.[].progression_goal_ids` and `base_root.raid_instance.progression_goal_ids` remain scalar `int32` snapshots in the inspected samples and are not in the referenced DSON vector type table. Keep them scalar until a non-empty sample or static rule confirms another encoding.
2. Quest threshold reward/loot branches are visible in the latest Prophet backup sample, but remain deeper scalar branches until more quest variants confirm whether they are generic reward thresholds, boss-specific payloads, or both.
3. Map facts now expose bounds, area roles, area-level door connections, tile coordinates, static tile metadata, populated state, entrance/final room resolution, dynamic areas, and sampled dynamic tile state. Deeper semantics such as gameplay meaning of dynamic `content`/`trap`/`mash`/`light`, static tile `type`/`obstacle`/texture ids, and `ext_data` remain pending.
4. Raid facts now expose quest, party, location, inventory, camp, mash, active battle summaries, enemies, initiative, and stat event summaries. Full `stat_database.entries[]` payload semantics and deep combat action/AI state remain intentionally summarized until a gameplay rule needs exact historical event parameters.
5. `base_root.darkest_dungeon_trinket_unlocks` is explicitly deferred because the current and research samples inspected so far have it empty.
6. Hash catalog coverage should be expanded only when future probes expose unresolved hash values that matter to a gameplay rule.

Gameplay systems such as building-upgrade scheduling or post-Ancestor story expansion should wait only when they directly depend on the remaining evidence gaps above. Otherwise, the current save facts are sufficient to start rule-shape experiments.
